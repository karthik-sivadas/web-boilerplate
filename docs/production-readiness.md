# Production readiness matrix

Workbench includes same-origin Better Auth accounts and local SQLite, plus browser-local workspace data. It is **not production-certified**, cloud sync, a backup service, or protection from browser-profile/devtools access. Built does not mean independently security-verified. **Local auth phase-2 gates pass; independent supervisor review and hosted deployment proof still block release.** See the [concrete test mapping and limits](auth-verification.md).

## Verification boundaries

Local source/Node/browser checks are not hosted Docker execution or target DNS/TLS/proxy/secret/monitoring acceptance. CI retains a real cookie session test after same-volume/same-secret container recreation, not just fresh signup. Its readiness polling is bounded. Docker availability must be measured, not assumed.

The current CSP uses unsafe-inline for Start hydration/styles; harden or explicitly risk-accept before sensitive deployment. Nitro and node:sqlite remain pinned prerelease/experimental risks. Dependency audit evidence is time-sensitive: the previous supervisor report recorded no moderate/high/critical findings and one low Windows-development-server esbuild advisory (GHSA-g7r4-m6w7-qqqr); that historical result is not a fresh audit of the monorepo lockfile.
