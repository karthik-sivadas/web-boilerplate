# Auth phase-2 verification and limits

Local `pnpm verify` passes **75 tests in 9 files and 14 browser executions**. All original 39 tests and six browser executions remain. The independent supervisor/security review and hosted Docker deployment proof are still release gates; this is not production certification.

## Implementation contract

`SessionBoundary` mounts real Better Auth SDK HTTP `getSession` requests (rolling cookie refresh), then `getSessionIdentity` (fresh database RPC, `disableRefresh: true`). Only matching user **and session IDs** unlock the workspace. Initial SSR/client state, pending requests, errors and mismatches never fall back to route-loader identity. RPC DTOs contain no session token.

Mount, focus, visibility, storage events, a token-free cross-tab channel and a visible-tab 60-second poll trigger reconciliation. Each HTTP/RPC/logout request has a 15-second abort deadline. Revalidation synchronously expires action leases and hides/unmounts private controls before awaiting query cancellation/clearing. Aborts plus generations reject late results, including same-user replacement. Every current workspace write/recovery/reset checks its lease. Unmounting intentionally discards unsaved dialogs/drafts even on an unchanged session. Revocation without a browser event is detected on the next visible poll, not instantaneously; server guards always check the database.

Logout never treats a failed response as confirmed revocation. It hides controls, clears queries, attempts SDK logout and verifies again; an existing valid session may reappear with an explicit uncertainty message. The channel carries only a random tab sender marker, never identity/token, and ignores the sender's own notification.

The native Nitro plugin uses the tested `createStartupGate`; every request class gets 503/no-store until migrations succeed. Rejection or the 60-second deadline fails closed and exits 1. A final Fetch-response policy applies private/no-store to non-health paths, including redirects and raw generated RPC responses, preserving distinct Set-Cookie fields. Read-only protected RPC rejection is an explicit HTTP 401 Response, not an Error that the non-SDK transport converts to 500.

## Compatibility, safety and remaining acceptance

The approved Zod-only root/app change to **4.5.4** restores Better Auth 1.7.3's `z.validate` IP-helper compatibility; production builds no longer emit the missing-export warning. Forwarded client IPs remain untrusted and rate limits intentionally share per-path database buckets. Do not enable proxy header trust without a reviewed deployment bridge. No other direct toolchain pins changed.

Local Gitleaks 8.30.1 on an isolated public-worktree mirror passes after the two authorized prose corrections; there is no broad allowlist. Existing private `.env`/`.data` were never read/copied/deleted. A separately installed public-source temporary workspace also booted `pnpm --filter web dev`, served health/signin200 and created only its own root `.data`, not an app-local store.

Docker was unavailable locally. The existing CI same-volume/same-secret cookie survival test remains, but no hosted result or deployed TLS/proxy/backup/restore acceptance is claimed. Manual screen-reader review, operational controls and independent security review remain required. Tests do not establish instant offline revocation, protection from browser-profile/devtools access, multi-tenant cloud authorization, email verification/recovery or multi-replica SQLite support.
