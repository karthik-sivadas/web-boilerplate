# Agent runner workflow

`pnpm agent --plan "brief"` is plan-only. `pnpm agent --apply .agent-runs/plans/<plan>.json` is the explicit execution step, and `pnpm agent --dry-run "brief"` prints the resolved roles, commands, and prompt composition without starting Pi. Add `--allow-research` only when a human explicitly authorizes Luna's bash-enabled research; a model's plan cannot grant that consent.

Defaults are `openai-codex/gpt-6-astra`, `gpt-5.6-terra`, and `gpt-5.6-luna`. `AGENT_<ROLE>_PROVIDER` and `AGENT_<ROLE>_MODEL` deliberately override them. Preflight uses the observed installed Pi 0.85 native `--list-models` text table (`provider model context max-out thinking images`) from either stream and compares its first two columns exactly. It is not an invented JSON-listing API or a promise of untested future Pi output formats; unrecognized tables and any missing/cross-provider pair fail without fallback.

Plans and completions are versioned strict Zod JSON. Plans have at most six acyclic tasks, safe owned paths, evidence criteria, risks, research questions, and fixed verification IDs. Planning requires a clean worktree. A saved plan records repository root, HEAD, and a hash of tracked/index/untracked content state; apply rechecks it and takes a repository-local lock. Tasks run once in deterministic topological order. Claimed and observed Git paths must be owned by the task. The fixed, non-model-selected `pnpm verify` gate always runs; one bounded Terra repair is allowed, followed by Astra review. A blocked review or unrepaired check fails. Nothing commits, pushes, or publishes.

Pi is launched with JSON mode, no session/resources/context discovery/project trust, explicit provider/model/tool allowlists, phase-specific role prompts, repository instructions, and stdin task data. The emitted phase prompt contains the full strict schema/example, brief, plan/task scope, acceptance mapping, and evidence boundary; dry-run prints that exact prompt and its argument vector without preflight or Pi. Pi 0.85 may emit user and tool-result message ends, assistant thinking and tool-call blocks, intermediate `toolUse` turns, multiple tool cycles, and a final assistant `stop`; only text from the latest valid final assistant turn is retained. Thinking is never persisted. Every assistant turn needs the requested provider/model identity; orphaned, duplicate, failed, or unfinished tool lifecycles, malformed/truncated/oversized output, cancellation, error/aborted/length outcomes, identity mismatches, timeout, or non-zero exit fail. It terminates POSIX process groups with bounded TERM/KILL cleanup (Windows receives child-level termination, not an equivalent shell sandbox). SIGINT/SIGTERM and a hard total-run deadline abort every phase. Ignored evidence lives in `.agent-runs`; raw thinking, credentials, and environment values are not logged. Verification is the fixed `pnpm verify` registry entry; `AGENT_TEST_VERIFY_BIN` is a test-fixture injection only and is never model-selected.

This is **trusted local execution, not a sandbox**. `--no-approve` disables Pi project-resource trust only; it is not command approval. A bash-capable model can modify files, access credentials, and use the network. Use a disposable container for untrusted briefs. Runner CI uses a fake Pi only and never contacts a provider.
